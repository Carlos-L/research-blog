### 2. 新协议数据后处理

那按照我这种协议，数据后处理包括数据预处理 → 参数估计 → 协调纠错 → 验证 → 隐私放大 → 最终密钥。你找我的理解，数据预处理可以复用，参数估计暂不考虑（已经解决），协调（包括量化）需要重新设计，纠错可以复用（不过LDPC的LLR要单独设计），验证可以复用，隐私放大可以复用，最终密钥率需要按照新的协议去计算
需要补充三点：数据预处理不是100%照搬，LDPC码本也要根据新信道调参，隐私放大算法可复用但压缩长度必须重新计算。

更准确的流程是：

${ \boxed{ \text{预处理与不变量构造} \rightarrow \text{参数估计} \rightarrow \text{联合量化与软解调} \rightarrow \text{LDPC纠错} \rightarrow \text{验证} \rightarrow \text{隐私放大} \rightarrow \text{最终密钥} } }$

## 各步骤能否复用

| 步骤                | 复用情况         | 你的协议需要做什么                   |
| ----------------- | ------------ | --------------------------- |
| 数据同步、ADC处理、SNU归一化 | 基本复用         | 增加不变量分块和归一化                 |
| 传统公共相位补偿          | 不使用          | 由公共相位不变量替代                  |
| 参数估计              | 按你当前结论暂视为已解决 | 最终仍需有限码长置信区间                |
| 反向协调框架            | 复用           | Bob成钥、Alice纠正到Bob           |
| 不变量坐标表示           | 重新设计         | 避免把8个量当8条独立信道               |
| 联合量化与比特标记         | 重新设计         | $\(F_B\rightarrow K_B\)$    |
| LLR软信息            | 重新设计         | 计算 $\(P(K_{B,j}\mid F_A)\)$ |
| LDPC译码算法          | 可以复用         | 码率、校验矩阵需要重新选择               |
| Syndrome发送        | 可以复用         | 实际长度计入泄漏                    |
| 纠错后验证             | 可以复用         | 验证哈希长度计入泄漏                  |
| 隐私放大算法            | 可以复用         | 输出长度按新协议计算                  |
| 经典信道认证            | 可以复用         | 必须贯穿整个公开通信过程                |
| 最终密钥率             | 重新计算         | 使用联合不变量信息和真实泄漏              |
