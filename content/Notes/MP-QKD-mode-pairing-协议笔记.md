# MP-QKD（Mode-Pairing QKD）协议笔记

> [!summary] 一句话理解
> Alice 和 Bob 在每个时隙独立随机设置发光强度和相位，把光送往不可信的 Charlie；Charlie 公布哪些时隙发生了单点击。随后 Alice 和 Bob **从已点击的时隙中选出两个进行配对**，再依据这两个时隙的本地强度或相对相位，判定 Z/X 基和比特。Z 对主要产生密钥，X 对主要检验相位相关性、约束窃听者的信息。

以下以原始 MP-QKD 论文的基本协议为主；实际系统还会加入诱骗态、有限码长分析和相位跟踪等处理。

## 1. 系统和时间基准

```text
Alice ──弱相干脉冲──┐
                    ├── Charlie：50:50 分束器 ── 探测器 L / R
Bob   ──弱相干脉冲──┘

公共时隙编号：  ... i ... j ...
                   ↑     ↑
              两个有效点击时隙事后配成一对
```

- Alice、Bob 的脉冲序列和 Charlie 的探测门按同一个**时隙编号**对齐。所谓“早/晚”，是相对**同一个已选中的时隙对**而言：若 $i<j$，$i$ 是早时隙，$j$ 是晚时隙；它们不必相邻。
- 每个时隙都做一次发送设置：例如强度选 $0$（真空设置，不主动发光）或 $\mu$（弱相干脉冲）。选 $\mu$ 也不保证实际有光子；弱相干态的光子数服从泊松分布，零光子仍有一定概率。
- 基本协议中每个非真空脉冲的调制相位可从 $[0,2\pi)$ 随机选择，**不要求每次只能取 $0$ 或 $\pi$**。Alice/Bob 各自记录自己的调制设置。
- Charlie 每个时隙公布 L 单点击、R 单点击、无点击或双击。基本配对步骤只使用**恰有一个探测器点击**的时隙；两个这样的时隙组成一对。

这里的“模式”主要是光学时间模式。“两次点击配对”指两次**不同时间**的有效单点击，不是要求同一时隙两个探测器同时点击。对应[原论文 Box 1](https://pmc.ncbi.nlm.nih.gov/articles/PMC9262923/)。


① 每个时隙
   Alice、Bob 各自随机选强度（0 或 μ）和相位，记录自己的设置
                         ↓
② 光到达 Charlie
   分束器干涉；Charlie 公布每个时隙是 L、R、无点击还是双击
                         ↓
③ 事后配对
   从“恰好一个探测器点击”的时隙中，选出 i、j 两次点击配成一对
                         ↓
④ 判基和筛选
   双方各自查看自己在 i、j 的强度：
   (0,μ) 或 (μ,0) → Z 对；(μ,μ) → X 对
   公布基类，保留符合协议条件的配对
                         ↓
⑤ 使用数据
   Z 对 → 按早/晚发光位置得到原始密钥
   X 对 → 比较相对相位，用 L/R 点击关系估计相位错误
                         ↓
⑥ 诱骗态估计、纠错、隐私放大 → 最终密钥

## 2. “随机选择”究竟在选什么？

至少有三种不同的随机性，不要混在一起：

1. **发光强度随机**：每个时隙独立选 $0$ 或 $\mu$；实践中还可能选诱骗态强度 $\nu$。选 $0$ 表示该时隙的真空设置。
2. **调制相位随机**：发光时选择并记录本地相位。随机相位不等于 Alice/Bob 对自己设置的相位一无所知。
3. **探测结果随机**：弱光、损耗与干涉使 Charlie 的 L/R 点击带有统计性。协议**事先不知道**哪些时隙会点击，所以等点击公布后才配对。

随机数应来自协议允许的私有随机源；强度和相位设置不能被 Eve 预先掌握。Alice/Bob 后续只公开协议要求公开的基、部分相位信息和抽样数据。

## 3. Charlie 的 L/R 能告诉我们什么？

L、R 是**分束器的两个输出端口**，不是“Alice 端口”和“Bob 端口”。若某个时隙只有 Alice 发出一束光，在理想对称条件下它也可在 L 或 R 点击；仅凭一次点击端口，Charlie 通常不能判断光来自谁。

若 Alice 和 Bob 的两路相干光**在同一时隙**到达分束器，且两路幅度匹配，理想模型中：

$$P(L\mid\text{点击})\approx\frac{1+\cos\Delta}{2},\qquad
P(R\mid\text{点击})\approx\frac{1-\cos\Delta}{2},$$

其中 $\Delta$ 是两路光**抵达 Charlie 时**的相位差。$\Delta=0$ 时倾向 L，$\Delta=\pi$ 时倾向 R；但单次弱光实验并非一定点击，噪声和失配也会导致偏差。这个说法适用于相干场的单光子干涉图像，**不要与“两路各恰好一颗全同光子的 HOM 干涉”混为一谈**。

L/R 的重要作用是：对一对时隙 $(i,j)$，公布的 $(L,L)$、$(L,R)$ 等结果可用于比较两次干涉的端口奇偶性。详见下文 X 基规则。

## 4. 两次点击如何变成 Z 基或 X 基？

假设 Charlie 在时隙 $i<j$ 各有一次有效单点击，两人事后把 $(i,j)$ 配成一对。每人根据**自己在这两时隙的强度设置**标记基：

| 本地强度 $(i,j)$ | 本地标记 | 直观含义 |
| --- | --- | --- |
| $(0,\mu)$ | Z | 只在晚时隙发送 |
| $(\mu,0)$ | Z | 只在早时隙发送 |
| $(\mu,\mu)$ | X | 两时隙都发送；比较本地相对相位 |
| $(0,0)$ | 真空类 | 用于参数估计等处理 |

Alice、Bob 公布基类并筛选可用的配对。**Z/X 不是每个单独时隙上预先贴好的标签，而是两次点击配成一对后才能判定的标签。**上表是原论文的基础版；加入诱骗态后，筛选规则还包括更多强度组合和真空类的参数估计用途。

### Z 对：把信息放在“早发还是晚发”

原论文的 Z 比特约定：

| 一方在 $(i,j)$ 的设置 | Alice 的比特 | Bob 的比特 |
| --- | ---: | ---: |
| $(0,\mu)$ | 0 | 1 |
| $(\mu,0)$ | 1 | 0 |

Bob 故意采用相反的本地映射。例如 Alice 设 $(\mu,0)$，Bob 设 $(0,\mu)$：在 $i$ 处主要是 Alice 发送，在 $j$ 处主要是 Bob 发送；两人都记为 **1**。实际点击仍受损耗、暗计数和多光子等影响，错误会在参数估计与纠错中处理。

这里“编码在时间上”更准确地说是编码在**配对后的两个时间模式的相对发光位置**上。Charlie 只报告有效时隙及 L/R 端口；他的一次 L 点击本身不带“Alice 发了”的标签。

### X 对：把信息放在“两脉冲的相对相位”

对本地 $(\mu,\mu)$，Alice 计算两次**已记录调制相位**之差：

$$\Delta\phi_A=(\phi_{A,j}-\phi_{A,i})\bmod 2\pi=\theta_A+\pi\kappa_A,$$

其中 $0\leq\theta_A<\pi$ 是**对齐角**，$\kappa_A\in\{0,1\}$ 是相位比特；Bob 同样得到 $\theta_B,\kappa_B$。两人公开对齐角，按协议保留匹配的 X 对，**不公开相位比特**。理想连续相位恰好相等的概率为零，实践中可用离散相位或相位分箱，并把误差纳入分析。

对保留的 X 对，Charlie 的两个点击端口决定 Bob 如何校正：

| Charlie 公布 | Bob 的处理 |
| --- | --- |
| $(L,L)$ 或 $(R,R)$ | 保持 $\kappa_B$ |
| $(L,R)$ 或 $(R,L)$ | 翻转 $\kappa_B$ |

例如 $\theta_A=\theta_B=0$，Alice 两时隙相对相位为 $0$，Bob 为 $\pi$，则 $\kappa_A=0,\kappa_B=1$。若公布 $(L,R)$，Bob 翻转为 0，和 Alice 对齐。**这只是映射规则的理想化例子**：两人每个时隙的跨用户相位差可未知，不能保证“前一次必然 L、后一次必然 R”。真实 X 对通过统计相关性来估计误差，原始方案主要用 Z 对产密钥。

以上强度、相位和点击映射均见[原论文 Box 1](https://pmc.ncbi.nlm.nih.gov/articles/PMC9262923/)。

## 5. 相位任意且随机，为什么 X 信息没有丢？

区分三个相位量：

- **本地调制相位** $\phi_{A,i}$、$\phi_{A,j}$：Alice 知道自己施加的设置，因此知道本地差 $\Delta\phi_A$；Bob 同理。
- **两人同一时隙在 Charlie 处的相位差** $d_i$：包含两台激光器和两条信道的未知漂移，通常不能仅凭本地调制设置精确知道。
- **两次时隙间的漂移变化** $d_j-d_i$：若配对间隔足够短，它可以较小或经参考信号估计。

因此 MP-QKD 利用的是**两次干涉的相关性**：即便共同的跨用户相位偏置 $d_i$ 未知，只要从 $i$ 到 $j$ 的变化受控，两个点击端口的“同/异”仍与两人的本地相位比特相关。随机相位的作用之一是协议所需的随机化；在 X 数据处理中，公开 $\theta$、保留 $\kappa$ 才形成可比较的信息。

实验中“知道自己的相位”主要指**知道调制器接受了什么相位指令，并经标定使指令与实际调制相符**；这不等于知道到达 Charlie 时的绝对光学相位。同步、激光相干性、调制器标定、参考脉冲/频偏估计以及配对窗口共同限制相位误差。因此“无需全局相位锁定”并不等于“无需任何相位控制或参考”。[原论文的配对窗口讨论](https://pmc.ncbi.nlm.nih.gov/articles/PMC9262923/)；[后续实验中的频偏跟踪](https://journals.aps.org/prx/abstract/10.1103/PhysRevX.15.021037)。

## 6. Eve 怎么被发现？安全性来自哪里？

用**单光子时间模式的简化图像**理解互补性：

$$|\text{早}\rangle=|i\rangle,\qquad |\text{晚}\rangle=|j\rangle,$$

$$|+\rangle=\frac{|i\rangle+|j\rangle}{\sqrt2},\qquad
|-\rangle=\frac{|i\rangle-|j\rangle}{\sqrt2}.$$

Z 信息关心光子在早还是晚；X 信息关心早晚两种可能性之间的**相干相位**。假设 Eve 为窃取 Z 信息，对经过的单光子强行测量“早还是晚”。在这个理想玩具模型中，输入 $|+\rangle$ 经测量后变为

$$\rho=\tfrac12|i\rangle\langle i|+\tfrac12|j\rangle\langle j|,$$

早晚之间的相干项消失。随后按 $|+\rangle/|-\rangle$ 测试，会有 **50%** 的随机错误。这个数字仅属于该理想化测量例子，**不能直接当成实际 MP-QKD 的 X 错误率**；真实协议还有跨用户未知相位、损耗、诱骗态筛选和条件点击。

协议检测 Eve 的方式是**统计估计**，不是逐个找出被窃听的脉冲：

1. 用诱骗态与不同强度的统计量，估计有效 Z 对中双方各贡献一个光子的部分 $q_{11}$。
2. 用保留的 X 对估计该单光子部分的相位错误 $e_{11}^{X}$，从而约束 Eve 对 Z 密钥可能知道多少。
3. 公开一部分数据估计 Z 误码，做纠错、隐私放大；若误差或参数估计不满足安全条件，就中止成钥。

即使 Charlie 本身由 Eve 控制，安全证明也必须覆盖他谎报点击并影响配对的可能性。原论文通过与固定配对方案的安全性建立联系来处理这一点。前提仍包括可信、充分表征的发送端以及**经过认证的经典通信**。参见[原论文安全性分析及密钥率公式](https://pmc.ncbi.nlm.nih.gov/articles/PMC9262923/)。

## 7. 为什么两次点击还能有较好的损耗标度？

设单时隙有效点击概率为 $p$，配对允许的最大时隙距离为 $l$。对原论文的简单配对策略，平均每发送时隙形成的配对数为

$$r_p(p,l)=\left[\frac{1}{p\,[1-(1-p)^l]}+\frac1p\right]^{-1}.$$

- **$l$ 很大且 $pl\gg1$**：通常能在窗口内找到下一次点击，约每两次点击组成一对，$r_p\approx p/2$。
- **$l=1$**：要求相邻时隙恰好都点击，$r_p=p^2/(1+p)\approx p^2$。

在对称链路中，单臂透过率 $\eta_s\sim\sqrt\eta$（$\eta$ 为 Alice 到 Bob 的总透过率），所以 $p\sim\sqrt\eta$。足够大的有效配对窗口可得到类似 $O(\sqrt\eta)$ 的标度；窗口过短时趋于 $O(\eta)$。**能不能用较长窗口，取决于两次时隙间相位相关性能维持多久**。这些是标度和渐近讨论，实际密钥率还受筛选比例、误码、暗计数和有限码长影响。[原论文式 (4)–(7)](https://pmc.ncbi.nlm.nih.gov/articles/PMC9262923/)。

## 8. MP-QKD 与 TF-QKD 的关系和区别

“TF-QKD”通常指一类双发送端到中间站、利用单光子干涉并可实现平方根损耗标度的方案；不同变体的 Z/X 定义、相位处理不同。不能把所有 TF 变体都概括为“必须实时全局相位锁定”。

| 问题 | MP-QKD | TF-QKD 的典型变体 |
| --- | --- | --- |
| 有效事件如何使用 | **事后把两次单点击时隙配对**，在时隙对上判基、映射比特 | 常以**单个时隙**的单点击作为候选事件，再按方案筛选 |
| Z 密钥信息 | 配对后本地两时隙的早/晚发光位置 | SNS-TF 中通常是单时隙的发送/不发送；PM-TF 的编码方式又不同 |
| X/相位信息 | 本地两个已配对时隙的**相对相位**，再结合两次 L/R 点击 | 通常处理同一时隙 Alice/Bob 到达 Charlie 的相位关系，并以具体协议做相位公开、筛选或补偿 |
| 相位要求 | 不要求知道每次跨用户绝对相位；需配对窗口内相位变化足够受控 | PM-QKD 可做事后相位补偿；SNS-TF 的 Z 数据本身不依赖单光子干涉，但 X 测试仍需相位信息 |
| 损耗标度 | 大有效配对窗口下可达到 $O(\sqrt\eta)$；窗口太短则退化 | 典型 TF 方案也追求 $O(\sqrt\eta)$ |

因此两者主要区别是**何时、以哪两个模式定义一个比特和测试事件**，而不是简单的“一个需要相位、另一个完全不需要相位”。参见[MP 原论文](https://pmc.ncbi.nlm.nih.gov/articles/PMC9262923/)、[PM-QKD 原论文](https://journals.aps.org/prx/abstract/10.1103/PhysRevX.8.031043)、[SNS-TF 原论文](https://journals.aps.org/pra/abstract/10.1103/PhysRevA.98.062323)。

## 9. 最容易混淆的五点

1. **L/R 是输出端口，不是 Alice/Bob 身份。**单次点击一般不能直接说明是谁发的。
2. **早/晚由配对的 $i,j$ 定义。**不要求两时隙相邻，但间隔受最大配对窗口 $l$ 限制。
3. **$0$ 强度设置与“选了 $\mu$ 却恰好零光子”不同。**前者是本地已知的发送决定；后者是弱相干态的光子数随机性。
4. **随机相位可以是任意角度。**X 比特来自本地相对相位的 $\pi$ 部分；对齐角用于筛选。
5. **X 测试是统计约束。**理想例子里 L/R 与 $0/\pi$ 的对应关系不是对每次实际点击的确定性判决；原协议主要用 Z 对出密钥。
